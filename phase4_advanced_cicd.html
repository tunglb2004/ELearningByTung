📸 Ảnh Chụp & Nhật Ký Khi Thất Bại

Tại Sao Cần Ảnh Chụp?

Khi kiểm thử thất bại, chỉ biết "kiểm thử thất bại" là không đủ. Làm thế nào? Vì sao? Ở đâu?

Ảnh chụp giúp:

  • ✅ Sửa lỗi trực quan: Xem trạng thái ứng dụng khi thất bại
  • ✅ Tái tạo lỗi: Nhà phát triển có thể thấy chính xác những gì đã xảy ra
  • ✅ Tài liệu: Ghi lại trạng thái ứng dụng cho báo cáo

Cách 1: TakesScreenshot Interface

import org.openqa.selenium.TakesScreenshot; import org.openqa.selenium.OutputType; import java.io.File; import org.apache.commons.io.FileUtils; /** * lấyẢnhChụp - Chụp cửa sổ trình duyệt hiện tại * * Cách hoạt động: * 1. Chuyển WebDriver thành TakesScreenshot interface * 2. Gọi getScreenshotAs(OutputType.FILE) * 3. Sao chép file vào thư mục đích * 4. Trả về đường dẫn file */ public static String lấyẢnhChụp(WebDriver driver, String tenẢnh) { try { // Bước 1: Chuyển driver thành TakesScreenshot // Tại sao chuyển? WebDriver interface không có method để chụp // TakesScreenshot interface này cung cấp method TakesScreenshot screenshot = (TakesScreenshot) driver; // Bước 2: Chụp ảnh dưới dạng FILE // getScreenshotAs(OutputType.FILE) trả về file tạm thời // Chúng ta cần lưu nó vào vị trí vĩnh viễn File source = screenshot.getScreenshotAs(OutputType.FILE); // Bước 3: Xác định đường dẫn đích // Tạo thư mục: screenshots/ nếu không có String duongDanDich = "screenshots/" + tenẢnh + ".png"; // Bước 4: Sao chép file tạm thời vào đích // FileUtils từ thư viện Apache Commons IO // copyFile(source, destination) sao chép file từ nguồn đến đích FileUtils.copyFile(source, new File(duongDanDich)); // Bước 5: Trả về đường dẫn để ghi nhật ký/báo cáo System.out.println("✅ Ảnh chụp đã lưu: " + duongDanDich); return duongDanDich; } catch (Exception e) { // Nếu chụp ảnh thất bại, in lỗi nhưng đừng làm hỏng kiểm thử System.out.println("❌ Không thể chụp ảnh: " + e.getMessage()); return null; } }
Giải Thích Chi Tiết:
• Chuyển TakesScreenshot: WebDriver interface không trực tiếp hỗ trợ ảnh chụp. Chúng ta chuyển thành TakesScreenshot interface có method để chụp.
• getScreenshotAs(): Chụp ảnh chụp và trả về dưới dạng file/bytes. OutputType.FILE = trả về dưới dạng File object.
• FileUtils.copyFile(): Selenium chụp trả về file tạm thời. Chúng ta sao chép vào vị trí vĩnh viễn (thư mục screenshots/) để giữ mãi mãi.
• Try-catch: Chụp ảnh có thể thất bại (vd: thư mục không tồn tại). Bắt exception và ghi nhật ký, đừng làm hỏng kiểm thử.

Cách 2: Ảnh Chụp Tự Động Khi Thất Bại Bằng Listener (Tốt Hơn!)

Thay vì chụp ảnh thủ công trong mỗi kiểm thử, sử dụng TestNG Listener để chụp tự động

public class NgheThiListener implements ITestListener { /** * khi KiểmThửThấtBại - Gọi tự động khi @Test method THẤT BẠI * * Tại sao hữu ích? * - Chụp ảnh tự động khi kiểm thử thất bại * - Không cần chụp ảnh thủ công trong mỗi kiểm thử * - Nhất quán trên tất cả các kiểm thử */ @Override public void onTestFailure(ITestResult result) { // result.getThrowable() lấy exception gây ra thất bại System.out.println("❌ Kiểm thử thất bại: " + result.getName()); // Lấy instance WebDriver // Cách làm: store trong static field, parameter injection, v.v. // Giả sử WebDriver lưu trong static field DriverFactory.getDriver() WebDriver driver = DriverFactory.getDriver(); // Chụp ảnh với tên kiểm thử if (driver != null) { lấyẢnhChụp(driver, result.getName() + "_THẤT_BẠI"); } } @Override public void onTestSuccess(ITestResult result) { System.out.println("✅ Kiểm thử thành công: " + result.getName()); } } // Đăng ký listener trong testng.xml <listeners> <listener class-name="listeners.NgheThiListener"/> </listeners>
🔊 "Khi test fail, screenshot very useful untuk understand what happened. Bapak dapat see aplikasi state, element positioning, error messages visually. TestNG tidak auto capture screenshots, jadi bapak perlu implement sendiri. Cara 1: manual screenshot di @AfterMethod. Setiap test method selesai, @AfterMethod trigger, capture screenshot. Cara 2: screenshot hanya kalo test fail - di catch block atau listener. Cara 3: listener pada failure - implementasi ITestListener interface, di onTestFailure() method, capture screenshot. Cara 1 simple but inefficient - screenshot terlalu banyak, makan storage. Cara 2 better - hanya save screenshot kalo ada masalah. Cara 3 best - automatic, tidak perlu manually call dalam setiap test. TakesScreenshot interface: cast driver ke TakesScreenshot, getScreenshotAs(OutputType.FILE), save ke file. Ví dụ: TakesScreenshot ts = (TakesScreenshot) driver. File screenshot = ts.getScreenshotAs(OutputType.FILE). String path = 'screenshots/' + System.currentTimeMillis() + '.png'. FileUtils.copyFile(screenshot, new File(path)). Selenium capture browser window saja, bukan full desktop. Jika bapak perlu capture lebih, gunakan third-party tools."

🎧 TestNG Listeners - Hook Vào Vòng Đời Kiểm Thử

Listeners Là Gì?

Listeners = Interfaces hook vào các sự kiện vòng đời kiểm thử

TestNG sẽ tự động gọi các method listener khi các sự kiện nhất định xảy ra:

  • ✅ Kiểm thử bắt đầu → onTestStart()
  • ✅ Kiểm thử thành công → onTestSuccess()
  • ✅ Kiểm thử thất bại → onTestFailure()
  • ✅ Kiểm thử bị bỏ qua → onTestSkipped()
  • ✅ Suite bắt đầu → onStart()
  • ✅ Suite kết thúc → onFinish()

Triển Khai Chi Tiết: Listener Để Ghi Nhật Ký & Báo Cáo

import org.testng.ITestListener; import org.testng.ITestResult; /** * NgheThiTuyChonListener - Triển khai hook vòng đời để ghi nhật ký, chụp ảnh, báo cáo */ public class NgheThiTuyChonListener implements ITestListener { /** * khi KiểmThửBắtĐầu - Gọi TRƯỚC @Test method bắt đầu * Hữu ích cho: ghi nhật ký bắt đầu kiểm thử, thiết lập tài nguyên từng kiểm thử */ @Override public void onTestStart(ITestResult result) { String tenKiểmThử = result.getName(); System.out.println("[BẮTĐẦU] " + tenKiểmThử); System.out.println("Lớp: " + result.getTestClass().getRealClass().getSimpleName()); } /** * khi KiểmThửThànhCông - Gọi SAU @Test method THÀNH CÔNG * * "Thành công" nghĩa là: * - Tất cả assertion pass * - Không có exception */ @Override public void onTestSuccess(ITestResult result) { System.out.println("✅ [THÀNH CÔNG] " + result.getName()); // Lấy thời gian thực thi long thoiGianThucThi = result.getEndMillis() - result.getStartMillis(); System.out.println("Thời gian thực thi: " + thoiGianThucThi + " ms"); } /** * khi KiểmThửThấtBại - Gọi SAU @Test method THẤT BẠI * @param result - ITestResult chứa thông tin thất bại * * "Thất bại" nghĩa là: * - Assertion thất bại (assertion trả về false) * - Exception không mong muốn (NoSuchElementException, v.v.) */ @Override public void onTestFailure(ITestResult result) { System.out.println("❌ [THẤT BẠI] " + result.getName()); // Lấy exception/error Throwable exception = result.getThrowable(); System.out.println("Thông báo lỗi: " + exception.getMessage()); // Lấy WebDriver để chụp ảnh WebDriver driver = DriverFactory.getDriver(); if (driver != null) { // Chụp ảnh với tên kiểm thử + "_THẤT_BẠI" String duongDanAnhChup = lấyẢnhChụp(driver, result.getName() + "_THẤT_BẠI"); System.out.println("📸 Ảnh chụp đã lưu: " + duongDanAnhChup); } // Thời gian thực thi cho kiểm thử thất bại long thoiGianThucThi = result.getEndMillis() - result.getStartMillis(); System.out.println("Thời gian thực thi: " + thoiGianThucThi + " ms"); } /** * khi KiểmThửBịBỏQua - Gọi khi @Test method BỊ BỎ QUA * Kiểm thử có thể bỏ qua vì: @Ignore, dependsOnMethods thất bại, điều kiện không đáp ứng, v.v. */ @Override public void onTestSkipped(ITestResult result) { System.out.println("⏭️ [BỊ BỎ QUA] " + result.getName()); } }

Đăng Ký Listener Trong testng.xml:

<?xml version="1.0" encoding="UTF-8"?> <suite name="DangNhapTestSuite"> <!-- Đăng ký listeners --> <listeners> <!-- NgheThiTuyChonListener sẽ tự động hook tất cả các kiểm thử --> <listener class-name="listeners.NgheThiTuyChonListener"/> </listeners> <test name="DangNhapTests"> <classes> <class name="tests.DangNhapTest"/> </classes> </test> </suite>
🔊 "Listeners adalah interface untuk hook ke test lifecycle events. ITestListener interface punya methods: onTestStart(), onTestSuccess(), onTestFailure(), onTestSkipped(). Ketika @Test method fail, TestNG automatically call onTestFailure(ITestResult result). Bapak bisa implement listener, override onTestFailure(), call screenshot method. Register listener di testng.xml: <listeners> <listener class-name='listeners.MyTestListener'/> </listeners>. Atau @Listeners annotation di test class. Keuntungan listener: centralized logic, auto capture semua tests tanpa modifikasi test code, flexible - bisa implement custom logic (log, send email, update database). Ví dụ: public class MyTestListener implements ITestListener { @Override public void onTestFailure(ITestResult result) { WebDriver driver = result.getInstance()... atau get dari static field. captureScreenshot(driver, result.getName()). System.out.println('Test failed: ' + result.getName()). } }. Listener very powerful untuk cross-cutting concerns - logging, monitoring, reporting yang apply ke semua tests."

🔄 Logic Thử Lại - Xử Lý Các Kiểm Thử Không Ổn Định

Kiểm Thử Không Ổn Định Là Gì?

Kiểm thử không ổn định = Kiểm thử đôi khi thành công, đôi khi thất bại mà không có thay đổi code

Nguyên nhân:

  • ❌ Vấn đề thời gian: Element không load đúng lúc (mạng chậm)
  • ❌ Vấn đề môi trường: Database timeout, API không khả dụng
  • ❌ Race conditions: Cập nhật đồng thời gây xung đột

Giải Pháp: Logic Thử Lại

Nếu kiểm thử thất bại, tự động thử lại (vd: 3 lần). Nếu thành công ở lần thử lại, tính là thành công.

/** * NgheThiThử Lại - Triển khai IRetryAnalyzer * TestNG gọi isRetryAvailable() sau khi kiểm thử thất bại * Nếu trả về true, TestNG tự động thử lại kiểm thử */ public class NgheThiThửLạiAnalyzer implements IRetryAnalyzer { private int soLanThuzLai = 0; private static final int MAX_THỬ_LẠI = 3; /** * retry - Gọi tự động bởi TestNG sau khi kiểm thử thất bại * @param result - ITestResult chứa thông tin thất bại * @return true nếu muốn thử lại, false nếu không * * Logic: * if (soLanThuzLai < MAX_THỬ_LẠI) { * soLanThuzLai++ * return true // Thử lại * } else { * return false // Hết lần thử lại, đánh dấu là thất bại * } */ @Override public boolean retry(ITestResult result) { if (soLanThuzLai < MAX_THỬ_LẠI) { System.out.println("🔄 Thử lại: " + result.getName() + " (Lần " + (soLanThuzLai + 1) + ")"); // Tăng bộ đếm thử lại soLanThuzLai++; // Trả về true = tiếp tục thử lại return true; } // Hết lần thử lại System.out.println("❌ Hết lần thử lại cho: " + result.getName()); return false; } }

Áp Dụng NgheThiThửLạiAnalyzer Vào Test Method:

@Test(retryAnalyzer = NgheThiThửLạiAnalyzer.class) public void testKhôngỔnĐịnh() { // Kiểm thử này sẽ được thử lại tới 3 lần nếu thất bại // Mô phỏng code phụ thuộc vào thời gian WebElement elem = wait.until( ExpectedConditions.visibilityOfElementLocated(By.id("dynamic")) ); // Đôi khi có thể timeout, nhưng thử lại sẽ giúp elem.click(); }

Đầu Ra Với Thử Lại:

[BẮTĐẦU] testKhôngỔnĐịnh Lần 1: TimeoutException - element không visible 🔄 Thử lại: testKhôngỔnĐịnh (Lần 2) [BẮTĐẦU] testKhôngỔnĐịnh (LẦN THỨ 2) Lần 2: TimeoutException - element vẫn không visible 🔄 Thử lại: testKhôngỔnĐịnh (Lần 3) [BẮTĐẦU] testKhôngỔnĐịnh (LẦN THỨ 3) Lần 3: THÀNH CÔNG! ✅ ✅ [THÀNH CÔNG] testKhôngỔnĐịnh (sau 3 lần) Tại sao? - Mạng chậm ở lần 1 & 2 - Lần 3, mạng phục hồi, element load - Kiểm thử cuối cùng thành công
⚠️ Cảnh Báo: Thử lại là giải pháp tạm thời. Nếu kiểm thử thất bại liên tục, hãy sửa nguyên nhân gốc (cải thiện logic chờ, ổn định môi trường). Đừng chỉ dựa vào thử lại.
🔊 "Flaky tests - tests yang sometimes pass sometimes fail tanpa code change. Cause: network latency, timing issues, environment instability. Solution: retry logic - retry test otomatis jika fail. IRetryAnalyzer interface - implement retry() method, return true jika retry, false jika tidak. Ví dụ: public class RetryAnalyzer implements IRetryAnalyzer { private int count = 0, maxRetry = 3. public boolean retry(ITestResult result) { if (count < maxRetry) { count++. return true. } return false. } }. @Test(retryAnalyzer=RetryAnalyzer.class) public void testFlaky() { ... }. Jika test fail, TestNG call retry(), jika return true, run test lagi. Kalo berhasil retry, test mark as PASSED. Kalo fail semua retries, test mark as FAILED. Pro tip: jangan rely 100% pada retry - itu is band-aid solution. Root cause adalah usually: network slow, element tidak wait properly, timing assumption wrong. Improve dengan explicit waits, stabilize environment. Retry hanya untuk edge cases."

🌐 Kiểm Thử Đa Trình Duyệt

Kiểm Thử Đa Trình Duyệt Là Gì?

Kiểm thử ứng dụng trên nhiều trình duyệt (Chrome, Firefox, Safari, Edge) để đảm bảo tương thích

Tại sao? Hành vi ứng dụng có thể khác nhau trên mỗi trình duyệt:

  • ❌ CSS rendering khác nhau
  • ❌ Thực thi JavaScript khác nhau
  • ❌ Hiệu suất khác nhau
  • ❌ Vấn đề tương thích

Cách: Mẫu Factory WebDriver

/** * DriverFactory - Mẫu Factory để tạo instance WebDriver * * Tại sao mẫu factory? * - Tập trung logic tạo driver * - Dễ dàng chuyển đổi trình duyệt * - Dễ dàng thêm tùy chọn driver */ public class DriverFactory { /** * lấyDriver - Tạo WebDriver dựa trên loại trình duyệt * @param loạiTrìnhDuyệt - "chrome", "firefox", "safari", "edge" * @return WebDriver instance */ public static WebDriver lấyDriver(String loạiTrìnhDuyệt) { WebDriver driver = null; switch (loạiTrìnhDuyệt.toLowerCase()) { case "chrome": driver = lấyChromeDriver(); break; case "firefox": driver = lấyFirefoxDriver(); break; case "safari": driver = lấySafariDriver(); break; case "edge": driver = lấyEdgeDriver(); break; default: System.out.println("❌ Trình duyệt không xác định: " + loạiTrìnhDuyệt); break; } return driver; } /** * lấyChromeDriver - Thiết lập Chrome driver với tùy chọn */ private static WebDriver lấyChromeDriver() { ChromeOptions options = new ChromeOptions(); // Thêm tùy chọn/arguments options.addArguments("--start-maximized"); // Bắt đầu toàn màn hình options.addArguments("--disable-blink-features=AutomationControlled"); // Vô hiệu hóa phát hiện tự động System.out.println("🌐 Khởi tạo Trình Duyệt Chrome"); return new ChromeDriver(options); } /** * lấyFirefoxDriver - Thiết lập Firefox driver */ private static WebDriver lấyFirefoxDriver() { FirefoxOptions options = new FirefoxOptions(); options.addArguments("--start-maximized"); System.out.println("🌐 Khởi tạo Trình Duyệt Firefox"); return new FirefoxDriver(options); } /** * lấySafariDriver - Thiết lập Safari driver * Lưu ý: Safari hỗ trợ hạn chế, chỉ macOS */ private static WebDriver lấySafariDriver() { System.out.println("🌐 Khởi tạo Trình Duyệt Safari (chỉ macOS)"); return new SafariDriver(); } /** * lấyEdgeDriver - Thiết lập Edge driver */ private static WebDriver lấyEdgeDriver() { EdgeOptions options = new EdgeOptions(); options.addArguments("--start-maximized"); System.out.println("🌐 Khởi tạo Trình Duyệt Edge"); return new EdgeDriver(options); } }

Test Đa Trình Duyệt Dựa Trên Dữ Liệu:

public class TestDangNhapĐaTrinhDuyệt { WebDriver driver; LoginPage loginPage; /** * @DataProvider - Cung cấp tên trình duyệt để kiểm thử * Trả về: [["chrome"], ["firefox"], ["safari"], ["edge"]] * Kiểm thử sẽ chạy 4 lần, mỗi lần với trình duyệt khác */ @DataProvider(name = "trìnhDuyệt") public Object[][] lấyTrìnhDuyệt() { return new Object[][] { {"chrome"}, {"firefox"}, {"safari"}, {"edge"} }; } @BeforeMethod public void thiết(String tenTrìnhDuyệt) { // Lấy instance WebDriver từ DriverFactory // Driver khác nhau dựa trên tham số tenTrìnhDuyệt driver = DriverFactory.lấyDriver(tenTrìnhDuyệt); // Điều hướng tới ứng dụng driver.get("https://example.com/login"); // Khởi tạo LoginPage loginPage = new LoginPage(driver); } /** * kiểmThửDangNhapTrênTấtCảTrìnhDuyệt - Kiểm thử đăng nhập trên tất cả trình duyệt * @DataProvider sẽ chạy này 4 lần (1 trình duyệt) */ @Test(dataProvider = "trìnhDuyệt") public void kiểmThửDangNhapTrênTấtCảTrìnhDuyệt(String tenTrìnhDuyệt) { System.out.println("Kiểm thử trên: " + tenTrìnhDuyệt); // Đăng nhập loginPage.login("john@example.com", "password123"); // Xác minh thông báo chào mừng (trên trình duyệt này) String thongBaoChaoMung = loginPage.getWelcomeMessage(); Assert.assertTrue( thongBaoChaoMung.contains("Chào mừng"), "Đăng nhập nên hoạt động trên " + tenTrìnhDuyệt ); System.out.println("✅ Đăng nhập thành công trên " + tenTrìnhDuyệt); } @AfterMethod public void dọnDẹp() { if (driver != null) { driver.quit(); } } }
🔊 "Real users pakai Chrome, Firefox, Safari, Edge. Aplikasi harus work di semua browsers. Cross-browser testing - test aplikasi di multiple browsers. Selenium support semua major browsers: ChromeDriver, GeckoDriver (Firefox), SafariDriver, EdgeDriver. Best practice: WebDriver factory pattern. Create DriverFactory class dengan static method getDriver(String browserName). Method check browserName, return appropriate driver. DriverFactory.getDriver('chrome') return ChromeDriver. getDriver('firefox') return FirefoxDriver. Combine dengan @DataProvider: provide array browser names. @DataProvider provide ['chrome', 'firefox', 'safari', 'edge']. @Test run 4 times, masing-masing browser. Benefits: single test logic, multiple browsers, easy add new browsers. Kalo 10 tests, 4 browsers = 40 test runs. Parallel execution dapat run 4 browsers simultaneously. Limitations: manage browsers locally adalah pain - need install ChromeDriver version match Chrome, GeckoDriver untuk Firefox, v.v. Solution: cloud services BrowserStack, Sauce Labs - remote browsers, no local setup. Tapi basic local testing: Firefox cukup untuk development, full cross-browser di CI/CD."

🔗 Tích Hợp CI/CD - Jenkins & GitHub Actions

CI/CD Là Gì?

CI (Tích Hợp Liên Tục) = Tự động chạy kiểm thử khi có thay đổi code

CD (Triển Khai Liên Tục) = Tự động triển khai ứng dụng nếu kiểm thử thành công

Quy Trình Làm Việc:

  • 1️⃣ Nhà phát triển push code lên Git
  • 2️⃣ CI/CD pipeline trigger (Jenkins, GitHub Actions, GitLab CI)
  • 3️⃣ Pipeline pull code mới nhất
  • 4️⃣ Pipeline chạy tất cả kiểm thử tự động
  • 5️⃣ Nếu kiểm thử thành công → triển khai. Nếu thất bại → chặn triển khai, thông báo cho nhà phát triển

Thiết Lập Jenkins Pipeline Cho Kiểm Thử Tự Động

/** * Jenkinsfile - Xác định CI/CD pipeline cho Jenkins * Vị trí: gốc dự án (cùng cấp với pom.xml) */ pipeline { // Chạy trên bất kỳ agent/node nào agent any // Xác định các biến môi trường environment { // URL cho ứng dụng kiểm thử ĐƯỜNG_DẪN_CƠ_SỞ = 'https://staging-app.example.com' THƯ_MỤC_BÁO_CÁO = 'test-reports' } // ============ CÁC GIAI ĐOẠN BUILD ============ stages { /** * Giai Đoạn 1: Thanh Tra - Pull code mới nhất từ Git */ stage('Thanh Tra') { steps { // Thanh tra code mới nhất từ nhánh main git branch: 'main', url: 'https://github.com/company/automation-tests.git' echo '✅ Code được thanh tra từ Git' } } /** * Giai Đoạn 2: Xây Dựng - Biên Dịch Code Java */ stage('Xây Dựng') { steps { echo '🔨 Đang xây dựng dự án...' // mvn clean compile: dọn sạch + biên dịch // -DskipTests: bỏ qua kiểm thử đơn vị (chúng ta chạy kiểm thử tích hợp riêng biệt) sh 'mvn clean compile -DskipTests' echo '✅ Xây dựng thành công' } } /** * Giai Đoạn 3: Kiểm Thử - Chạy tất cả kiểm thử tự động */ stage('Kiểm Thử Tự Động') { steps { echo '🧪 Đang chạy kiểm thử tự động...' // mvn test: chạy tất cả kiểm thử trong src/test/java // -Dsuites: chạy testng.xml cụ thể sh 'mvn test -Dsuites=testng.xml -Dbrowser=chrome' echo '✅ Kiểm thử hoàn thành' } } /** * Giai Đoạn 4: Tạo Báo Cáo - Tạo báo cáo kiểm thử */ stage('Tạo Báo Cáo') { steps { echo '📊 Đang tạo báo cáo kiểm thử...' // Tạo báo cáo HTML (được đề cập trong slide tiếp theo) // Jenkins cũng tự động thu thập ảnh chụp echo '✅ Báo cáo đã được tạo' } } /** * Giai Đoạn 5: Xuất Bản Kết Quả - Xuất bản báo cáo & artifacts */ stage('Xuất Bản Kết Quả') { steps { // Xuất bản kết quả kiểm thử junit 'target/surefire-reports/*.xml' // Lưu trữ báo cáo HTML publishHTML([ reportDir: 'test-reports', reportFiles: 'index.html', reportName: 'Báo Cáo Kiểm Thử Tự Động' ]) // Lưu trữ ảnh chụp archiveArtifacts artifacts: 'screenshots/**', allowEmptyArchive: true } } /** * Giai Đoạn 6: Triển Khai (Tùy Chọn) - Triển khai nếu kiểm thử thành công */ stage('Triển Khai') { when { // Chỉ triển khai nếu các giai đoạn trước thành công expression { currentBuild.result == null || currentBuild.result == 'SUCCESS' } } steps { echo '🚀 Đang triển khai ứng dụng...' // Script triển khai ở đây sh './deploy.sh' } } } // ============ CÁC HÀNH ĐỘNG SAU BUILD ============ post { // Luôn chạy, bất kể thành công/thất bại always { echo '🏁 Pipeline hoàn thành' } // Chạy nếu pipeline THẤT BẠI failure { echo '❌ Pipeline THẤT BẠI' // Gửi thông báo email emailext( subject: 'Kiểm Thử Tự Động THẤT BẠI', body: 'Kiểm tra Jenkins: $BUILD_URL', to: 'qa-team@company.com' ) } // Chạy nếu pipeline THÀNH CÔNG success { echo '✅ Pipeline THÀNH CÔNG' emailext( subject: 'Kiểm Thử Tự Động THÀNH CÔNG', body: 'Tất cả kiểm thử đã thành công! Sẵn sàng triển khai.', to: 'qa-team@company.com' ) } } }

Quy Trình Thực Thi Jenkins Pipeline:

[Pipeline Bắt Đầu] Thanh Tra ✅ (Git pull code mới nhất) Xây Dựng ✅ (mvn clean compile) Kiểm Thử Tự Động ✅ (mvn test) - testDangNhapHợpLệ ✅ THÀNH CÔNG - testDangNhapKhôngHợpLệ ❌ THẤT BẠI (ảnh chụp được lưu) - testĐăngXuất ✅ THÀNH CÔNG - testĐăngXuấtVôiBrowserClose ✅ THÀNH CÔNG Tạo Báo Cáo ✅ (Báo cáo HTML được tạo) Xuất Bản Kết Quả ✅ (Báo cáo được xuất bản) Triển Khai ❌ BỊCHẶN (kiểm thử thất bại, không thể triển khai) Tóm Tắt: - Tổng Kiểm Thử: 4 - Thành Công: 3 - Thất Bại: 1 - Tỷ Lệ Thành Công: 75% - Trạng Thái: THẤT BẠI (triển khai bị chặn) Email: qa-team@company.com Chủ Đề: Kiểm Thử Tự Động THẤT BẠI Nội Dung: Kiểm tra Jenkins để biết chi tiết
🔊 "CI/CD - Continuous Integration/Deployment. Workflow: developer commit code → CI/CD trigger → run tests → report results → deploy jika tests pass. TestNG tests dapat integrate dengan Jenkins atau GitHub Actions. Jenkins setup: create Freestyle job atau Pipeline job. Pull latest code. Run Maven/Gradle để compile. Run TestNG tests: mvn test. Publish reports. GitHub Actions: create .github/workflows/tests.yml file. On push event, trigger workflow. Run tests: mvn test. Upload artifacts (reports, screenshots). Pipeline Benefits: automatic testing pada setiap commit. Developers immediately notified jika break tests. Jika tests fail, deployment blocked. Quality gate - code tidak deploy sampai tests pass. Dalam testng.xml, bisa specify: <suite thread-count='8' parallel='methods'> untuk run parallel di CI server. 10 tests × 5 seconds = 50 seconds sequential, parallel 8 threads = 6-7 seconds. Major speedup."

📊 Báo Cáo Kiểm Thử - Tạo Báo Cáo HTML

Báo Cáo Kiểm Thử Là Gì?

Báo cáo kiểm thử = Tóm tắt kết quả thực thi kiểm thử (thành công, thất bại, bỏ qua, thời gian thực thi)

Định Dạng:

  • ✅ Báo Cáo HTML: Trực quan, dễ đọc, bao gồm biểu đồ
  • ✅ Báo Cáo XML: Có thể đọc máy, để CI/CD phân tích
  • ✅ Báo Cáo PDF: Tài liệu chính thức, dễ chia sẻ
  • ✅ Báo Cáo Email: Tóm tắt được gửi qua email

TestNG Báo Cáo Tích Hợp

TestNG tự động tạo báo cáo XML. Vị trí: target/surefire-reports/

Trình Tạo Báo Cáo HTML Tùy Chỉnh

/** * TạoBáoCáo - Tạo file HTML với kết quả kiểm thử * Tại sao tùy chỉnh? Báo cáo tích hợp cơ bản. Báo cáo tùy chỉnh có thể: * - Thêm ảnh chụp (liên kết trong báo cáo) * - Tùy chỉnh kiểu dáng (màu sắc thương hiệu, logo) * - Thêm metrics (thời gian thực thi trên mỗi kiểm thử, % thành công, v.v.) */ public class TạoBáoCáo { /** * tạoBáoCáo - Tạo file HTML với kết quả kiểm thử * @param kếtQuảKiểmThử - List chứa tất cả thông tin kiểm thử * @param duongDanBáoCáo - Nơi để lưu báo cáo HTML */ public static void tạoBáoCáo(List kếtQuảKiểmThử, String duongDanBáoCáo) { try { // StringBuilder để xây dựng chuỗi HTML StringBuilder html = new StringBuilder(); // ============ HTML HEAD ============ html.append("<!DOCTYPE html><html>"); html.append("<head>"); html.append("<title>Báo Cáo Kiểm Thử Tự Động</title>"); // Thêm kiểu CSS html.append("<style>"); html.append("body { font-family: Arial; margin: 20px; }"); html.append("h1 { color: #333; }"); html.append("table { border-collapse: collapse; width: 100%; }"); html.append("th, td { border: 1px solid #ddd; padding: 12px; text-align: left; }"); html.append("th { background-color: #4CAF50; color: white; }"); html.append(".thanh-cong { color: green; font-weight: bold; }"); html.append(".that-bai { color: red; font-weight: bold; }"); html.append("</style>"); html.append("</head>"); // ============ HTML BODY ============ html.append("<body>"); // Tiêu đề & Tóm tắt html.append("<h1>🧪 Báo Cáo Kiểm Thử Tự Động</h1>"); html.append("<p>Ngày Thực Thi: " + new Date() + "</p>"); // Tính toán metrics int tổngKiểmThử = kếtQuảKiểmThử.size(); long kiểmThửThànhCông = kếtQuảKiểmThử.stream() .filter(r -> r.làThànhCông()).count(); long kiểmThửThấtBại = tổngKiểmThử - kiểmThửThànhCông; double tỷLệThànhCông = (kiểmThửThànhCông * 100 / tổngKiểmThử); // Phần tóm tắt html.append("<h2>Tóm Tắt</h2>"); html.append("<table>"); html.append("<tr><th>Tổng Kiểm Thử</th><td>" + tổngKiểmThử + "</td></tr>"); html.append("<tr><th>Thành Công</th><td class='thanh-cong'>" + kiểmThửThànhCông + "</td></tr>"); html.append("<tr><th>Thất Bại</th><td class='that-bai'>" + kiểmThửThấtBại + "</td></tr>"); html.append("<tr><th>Tỷ Lệ Thành Công</th><td>" + String.format("%.2f", tỷLệThànhCông) + "%</td></tr>"); html.append("</table><br/>"); // Bảng chi tiết kiểm thử html.append("<h2>Chi Tiết Kiểm Thử</h2>"); html.append("<table>"); html.append("<tr><th>Tên Kiểm Thử</th><th>Trạng Thái</th><th>Thời Gian (ms)</th><th>Ảnh Chụp</th></tr>"); // Lặp qua mỗi kết quả kiểm thử for (KếtQuảKiểmThử result : kếtQuảKiểmThử) { html.append("<tr>"); html.append("<td>" + result.getTênKiểmThử() + "</td>"); // Trạng Thái: Thành Công (xanh) hoặc Thất Bại (đỏ) String lớpTrạngThái = result.làThànhCông() ? "thanh-cong" : "that-bai"; String trạngThái = result.làThànhCông() ? "✅ THÀNH CÔNG" : "❌ THẤT BẠI"; html.append("<td class='" + lớpTrạngThái + "'>" + trạngThái + "</td>"); // Thời gian thực thi html.append("<td>" + result.getThờiGianThựcThi() + "</td>"); // Liên kết ảnh chụp (nếu có) String duongDanAnhChup = result.getDuongDanAnhChup(); if (duongDanAnhChup != null && !duongDanAnhChup.isEmpty()) { html.append("<td><a href='" + duongDanAnhChup + "'>Xem</a></td>"); } else { html.append("<td>-</td>"); } html.append("</tr>"); } html.append("</table>"); html.append("</body></html>"); // Ghi HTML vào file FileWriter writer = new FileWriter(duongDanBáoCáo); writer.write(html.toString()); writer.close(); System.out.println("✅ Báo cáo được tạo: " + duongDanBáoCáo); } catch (IOException e) { System.out.println("❌ Không thể tạo báo cáo: " + e.getMessage()); } } }
🔊 "TestNG auto generate default HTML report dalam test-output folder. Report contain: test summary (passed/failed/skipped), detailed test results, execution time, stack traces. Tapi custom report often needed untuk: include screenshots, better styling, custom metrics. Tools: ExtentReports (powerful, generate beautiful reports), Allure (modern, interactive). Atau write custom report generator: iterate through test results, generate HTML file, include screenshots, charts. Custom report bisa include: test name, status, execution time, screenshot on failure, log messages, assertions. Reporting important untuk: document test coverage, communicate results to stakeholders, track trends over time (pass rate decreasing? itu sign problems)."
