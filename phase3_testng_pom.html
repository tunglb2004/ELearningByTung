🧪 TestNG Là Gì?

Định Nghĩa

TestNG = Testing Framework cho Java, similar to JUnit nhưng powerful hơn.

TestNG giúp bạn:

  • ✅ Organize test cases thành groups & classes
  • ✅ Run tests theo order, dependencies, priorities
  • ✅ Run tests in parallel (nhanh hơn)
  • ✅ Generate HTML reports
  • ✅ Parametrize tests (data-driven testing)
  • ✅ Setup/teardown fixtures (@BeforeClass, @AfterClass)

Ví Dụ: Với vs Không Có TestNG

❌ Không có TestNG (JUnit):

public class TestLogin { WebDriver driver; @Before public void setUp() { driver = new ChromeDriver(); } @Test public void testValidLogin() { // Test code } @Test public void testInvalidLogin() { // Test code } @After public void tearDown() { driver.quit(); } } // Khi run: không control thứ tự, không parallel, output basic

✅ Với TestNG:

@BeforeSuite // Run 1 lần trước tất cả tests @BeforeTest // Run trước mỗi test tag trong XML @BeforeClass // Run 1 lần trước tất cả methods trong class @BeforeMethod // Run trước mỗi @Test method @Test @AfterMethod @AfterClass @AfterTest @AfterSuite // Khi run: control order, parallel, HTML reports

Lợi Ích Của TestNG

Feature JUnit TestNG
Organize tests Basic ✅ Powerful (groups, priorities)
Parallel execution Khó ✅ Easy (1 line XML)
Parameterization @Parameterized ✅ @DataProvider, @Parameters
Fixtures @Before/@After ✅ 4 levels (@BeforeSuite, @BeforeTest, @BeforeClass, @BeforeMethod)
Reports Basic XML ✅ HTML, detailed
🔊 "TestNG cung cấp annotations để hook vào test lifecycle. Annotations là metadata - Java cung cấp mechanism để mark method/class/field với extra info. TestNG sẽ scan class, tìm methods với annotations, rồi execute theo order. Annotations bắt đầu bằng @ symbol. @BeforeSuite - run once trước ALL tests. Useful để setup global resources như database, server. @AfterSuite - run once sau ALL tests. Useful để cleanup global resources. @BeforeTest - run trước mỗi test tag ở testng.xml (chúng ta sẽ học testng.xml sau). @AfterTest - run sau mỗi test tag. @BeforeClass - run once trước mỗi test class. Nếu class có 10 test methods, @BeforeClass run 1 lần, không 10 lần. @AfterClass - run once sau mỗi test class. @BeforeMethod - run trước MỖI test method. Nếu class có 10 test methods, @BeforeMethod run 10 lần. @AfterMethod - run sau MỖI test method. @Test - mark method là test method. TestNG sẽ execute methods có @Test annotation. Lifecycle hierarchy là: @BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test → @AfterMethod → @AfterClass → @AfterTest → @AfterSuite. Nếu có 2 test methods, flow sẽ là: @BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test 1 → @AfterMethod → @BeforeMethod → @Test 2 → @AfterMethod → @AfterClass → @AfterTest → @AfterSuite."

Step 2: TestNG Annotations Hierarchy

public class TestNGExample { // 1. Run 1 lần ở đầu, trước tất cả tests @BeforeSuite public void beforeSuite() { System.out.println("1. Before Suite"); } // 2. Run trước mỗi <test> tag trong testng.xml @BeforeTest public void beforeTest() { System.out.println("2. Before Test"); } // 3. Run 1 lần trước tất cả @Test methods trong class @BeforeClass public void beforeClass() { System.out.println("3. Before Class"); } // 4. Run trước MỖI @Test method @BeforeMethod public void beforeMethod() { System.out.println("4. Before Method - setup"); } // Actual test method 1 @Test public void testLogin() { System.out.println("[TEST 1] Login Test"); } // Actual test method 2 @Test public void testLogout() { System.out.println("[TEST 2] Logout Test"); } // 5. Run sau MỖI @Test method @AfterMethod public void afterMethod() { System.out.println("5. After Method - teardown"); } // 6. Run 1 lần sau tất cả @Test methods @AfterClass public void afterClass() { System.out.println("6. After Class"); } // 7. Run sau mỗi <test> tag @AfterTest public void afterTest() { System.out.println("7. After Test"); } // 8. Run 1 lần ở cuối, sau tất cả tests @AfterSuite public void afterSuite() { System.out.println("8. After Suite"); } }

Output Khi Run:

1. Before Suite 2. Before Test 3. Before Class 4. Before Method - setup [TEST 1] Login Test 5. After Method - teardown 4. Before Method - setup [TEST 2] Logout Test 5. After Method - teardown 6. After Class 7. After Test 8. After Suite Giải thích: - BeforeSuite chạy 1 lần ở đầu - BeforeTest & AfterTest chạy cho <test> tag - BeforeClass & AfterClass chạy 1 lần cho class - BeforeMethod & AfterMethod chạy trước/sau MỖI test - Nếu có 2 @Test methods: * BeforeMethod/AfterMethod sẽ chạy 2 lần (mỗi test 1 lần) * BeforeClass/AfterClass chạy 1 lần
Giải thích Chi Tiết:
• BeforeSuite/AfterSuite: Run 1 lần cho toàn bộ test suite (setup database, cleanup resources)
• BeforeTest/AfterTest: Run 1 lần per <test> tag trong XML (dùng khi có multiple <test> tags)
• BeforeClass/AfterClass: Run 1 lần per class (một class có 10 test methods, BeforeClass chạy 1 lần, setup shared resources)
• BeforeMethod/AfterMethod: Run trước/sau MỖI @Test (nếu 10 test methods, BeforeMethod chạy 10 lần, setup individual test)
💡 Tip: Dùng BeforeSuite/BeforeTest để setup browser 1 lần. Dùng BeforeMethod để reset state trước mỗi test. Dùng AfterMethod để clear cookies/cache.
🔊 "Hãy xem code ví dụ. Import TestNG annotations từ org.testng. Tạo public class LoginTests. Khai báo WebDriver driver (global variable để access trong các methods). Viết @BeforeSuite method - setup Selenium. Nó run once, trước tất cả tests. Viết @BeforeMethod method - reset browser state, navigate to login page. Nó run trước mỗi test method. Vì vậy nếu test 1 login fail, browser có lỗi state, @BeforeMethod sẽ reset nó cho test 2. Viết @Test method testValidLogin - test login với credentials hợp lệ. Viết @Test method testInvalidLogin - test login với invalid credentials. Viết @AfterMethod method - logout, clear cookies, reset state. Viết @AfterSuite method - close browser, cleanup resources. Khi bạn run class như JUnit, TestNG sẽ automatically execute methods theo lifecycle. Không cần main() method, không cần viết orchestration code. TestNG handle tất cả."

🧪 TestNG + Selenium Integration

Practical Example: Login Test with TestNG

import org.testng.annotations.*; import org.openqa.selenium.*; import org.openqa.selenium.chrome.ChromeDriver; public class LoginTestWithTestNG { // Declare WebDriver as class variable // Why? So all @Test methods dapat access WebDriver driver; WebDriverWait wait; // ============ SETUP PHASE ============ // Run 1 lần sebelum semua tests di class ini // Dgunakan untuk: initialize WebDriver, load baseURL, login sekali @BeforeClass public void beforeClass() { System.out.println("[Setup] Initializing WebDriver"); // Create new Chrome browser instance driver = new ChromeDriver(); // Initialize WebDriverWait (explicit waits) wait = new WebDriverWait(driver, Duration.ofSeconds(10)); // Open application base URL driver.get("https://example.com"); // Maximize browser window untuk better visibility driver.manage().window().maximize(); } // ============ PER-TEST SETUP ============ // Run SEBELUM MASING-MASING @Test method // Digunakan untuk: reset state, clear cookies, login if needed @BeforeMethod public void beforeMethod(Method method) { System.out.println("[Before Test] " + method.getName()); // Navigate to login page (reset state) driver.navigate().to("https://example.com/login"); // Clear browser cookies (reset session) driver.manage().deleteAllCookies(); } // ============ TEST METHODS ============ // Test 1: Valid login dengan correct credentials // priority=1: run ini duluan (default priority=0) @Test(priority=1) public void testValidLogin() { System.out.println("[TEST 1] Testing valid login"); // Find username input element WebElement username = wait.until( ExpectedConditions.visibilityOfElementLocated(By.id("username")) ); // Type username username.sendKeys("john@example.com"); // Find password input WebElement password = driver.findElement(By.id("password")); // Type password password.sendKeys("password123"); // Click login button WebElement loginBtn = driver.findElement(By.id("login-btn")); loginBtn.click(); // Wait for welcome message to appear (indicator ng successful login) WebElement welcome = wait.until( ExpectedConditions.visibilityOfElementLocated(By.id("welcome-msg")) ); // Assert (verify) welcome message contains "Welcome" Assert.assertTrue( welcome.getText().contains("Welcome"), "Welcome message should appear after successful login" ); } // Test 2: Invalid login dengan wrong password // priority=2: run ito second @Test(priority=2) public void testInvalidLogin() { System.out.println("[TEST 2] Testing invalid login"); // Fill username driver.findElement(By.id("username")).sendKeys("john@example.com"); // Fill wrong password driver.findElement(By.id("password")).sendKeys("wrongpassword"); // Click login driver.findElement(By.id("login-btn")).click(); // Wait for error message WebElement errorMsg = wait.until( ExpectedConditions.visibilityOfElementLocated(By.id("error-msg")) ); // Assert error message shows Assert.assertTrue( errorMsg.getText().contains("Invalid credentials"), "Error message should show for wrong password" ); } // Test 3: Login dengan empty username @Test(priority=3) public void testLoginEmptyUsername() { System.out.println("[TEST 3] Testing login dengan empty username"); // Don't fill username (leave empty) // Just fill password driver.findElement(By.id("password")).sendKeys("password123"); // Click login button driver.findElement(By.id("login-btn")).click(); // Wait for error message WebElement errorMsg = wait.until( ExpectedConditions.visibilityOfElementLocated(By.id("error-msg")) ); // Assert validation error shows Assert.assertTrue( errorMsg.getText().contains("Username required"), "Validation error should show" ); } // ============ TEARDOWN PHASE ============ // Run SESUDAH SETIAP @Test method // Digunakan untuk: cleanup, logout, reset browser state @AfterMethod public void afterMethod(Method method) { System.out.println("[After Test] " + method.getName()); // Clear browser cookies untuk isolate tests // (prevent test interference) driver.manage().deleteAllCookies(); // Clear browser cache by deleting IndexedDB ((JavascriptExecutor) driver).executeScript("window.indexedDB.deleteDatabase('myDB')"); } // Run 1 lần setelah semua @Test methods // Digunakan untuk: close browser, cleanup resources @AfterClass public void afterClass() { System.out.println("[Cleanup] Closing browser"); // Close all browser windows and end session // quit() = close all windows + end WebDriver session // close() = close current window only (not recommended) driver.quit(); } }

Output Ketika Run:

[Setup] Initializing WebDriver [Before Test] testValidLogin [TEST 1] Testing valid login ✅ Assert passed: Welcome message appears [After Test] testValidLogin [Before Test] testInvalidLogin [TEST 2] Testing invalid login ✅ Assert passed: Error message shows [After Test] testInvalidLogin [Before Test] testLoginEmptyUsername [TEST 3] Testing login dengan empty username ✅ Assert passed: Validation error shows [After Test] testLoginEmptyUsername [Cleanup] Closing browser Total Tests Run: 3 Passed: 3 Failed: 0 Skipped: 0
Mengapa Structure Ini Lebih Baik?
1. BeforeClass: Initialize driver 1x (efficient, save time)
2. BeforeMethod: Reset state sebelum masing-masing test (isolate tests, prevent interference)
3. Priority: Control test execution order (test valid login dulu, baru test invalid)
4. AfterMethod: Cleanup cookies/cache (reset for next test)
5. AfterClass: Close browser (save resources)
6. Assert: Verify hasil (test pass/fail based on assertion)
🔊 "Assertions là statements để verify expected vs actual. Nếu expected match actual, assertion pass, test continue. Nếu không match, assertion fail, throw AssertionError, test fail. Assertions là core của testing - nếu không assert, code chỉ run tapi tidak verify. TestNG cung cấp assertion methods. Assert.assertEquals(expected, actual) - check expected equal actual. Assert.assertNotEquals(expected, actual) - check not equal. Assert.assertTrue(condition) - check condition true. Assert.assertFalse(condition) - check condition false. Assert.assertNull(object) - check object null. Assert.assertNotNull(object) - check object not null. Assert.assertSame(obj1, obj2) - check obj1 dan obj2 adalah same object (reference). Assert.assertNotSame - check not same object. Assert.fail('message') - explicitly fail test dengan message. Assert.fail() throw AssertionError, test immediately fail. Ví dụ test case: login, get welcome message, assert message contains 'Welcome'. Jika message tidak contain, assertion fail, test fail. Developers akan lihat assertion error dan tahu apa yang wrong. Best practice: buat meaningful assertion messages. Assert.assertEquals('Welcome john', welcomeMsg, 'Welcome message should contain user name'). Message akan help debugging ketika assertion fail."

📄 Page Object Model (POM) - Intro

Problem Tanpa POM

Ketika script besar (100+ test cases), code menjadi:

  • ❌ Berulang-ulang (repeat locators di banyak places)
  • ❌ Sulit maintain (UI change → modify 100+ places)
  • ❌ Sulit baca (campur element locators + test logic)
  • ❌ Sulit scale (tidak organize)

Apa Itu Page Object Model?

POM = Design pattern untuk separate element locators & page actions dari test logic

Konsep Utama POM:

  • 1️⃣ Buat 1 class per page (LoginPage, HomePage, DashboardPage)
  • 2️⃣ Simpan semua locators di class sebagai private variables
  • 3️⃣ Buat methods untuk setiap action (fillUsername(), fillPassword(), clickLogin())
  • 4️⃣ Test classes hanya call page methods (tidak access locators directly)

Struktur POM

src/test/java/ ├── pages/ │ ├── LoginPage.java (locators + actions for login page) │ ├── HomePage.java (locators + actions for home page) │ └── DashboardPage.java (locators + actions for dashboard) └── tests/ ├── LoginTest.java (only test logic, call page methods) ├── HomeTest.java └── DashboardTest.java

Apa Keuntungannya?

  • ✅ Maintainability: Locator change → update 1 place (LoginPage class)
  • ✅ Readability: Test code clean, jelas intent
  • ✅ Reusability: Semua test classes bisa reuse same page methods
  • ✅ Scalability: Add 100 more tests hanya dengan kombinasi existing methods
💡 Analogi: Tanpa POM kayak mencampur kitchen (where you cook) dengan dining room (where you eat). Dengan POM, pisah: kitchen punya recepes (LoginPage), dining room hanya order (LoginTest).
🔊 "Ketika project besar, ada ratusan test classes. Baiknya tidak run semua setiap kali. TestNG menyediakan testng.xml file untuk organize dan configure tests. File ini adalah XML configuration file mana bisa specify: suite name, test names, classes to include/exclude, parallel execution, listeners, parameters. Struktur: <suite> tag adalah root, di dalamnya <test> tags, di dalamnya <classes> atau <methods> tags. Ví dụ, testng.xml: <suite name='LoginSuite'> specify suite name. <test name='LoginTests'> specify test group. <classes> <class name='tests.LoginTest'/> </classes> specify class. Ketika run testng.xml, TestNG sẽ scan class, tìm @Test methods, run chúng. Bạn bisa specify specific methods bằng <methods>. Ví dụ <methods> <include name='testValidLogin'/> </methods> sẽ run hanya testValidLogin, skip testInvalidLogin. Best practice: organize tests dalam testng.xml, run xml file, tidak run class individual. Nó memberikan flexibility untuk choose tests."

📄 Page Object Model - Detailed Example

Step 1: Create LoginPage Class (POM)

import org.openqa.selenium.*; import org.openqa.selenium.support.ui.*; /** * LoginPage - Page Object Class * Bertanggung jawab untuk: * 1. Menyimpan semua locators untuk login page * 2. Menyediakan methods untuk interact dengan page * 3. Melakukan waits dan assertions untuk page */ public class LoginPage { // ============ WEBDRIVER & WAIT ============ // Store WebDriver reference // Constructor akan initialize ini private WebDriver driver; // Store WebDriverWait reference // Untuk explicit waits private WebDriverWait wait; // ============ LOCATORS ============ // ALL locators simpan di sini sebagai private // Why private? Tidak boleh diakses dari test class // Test class hanya call methods, tidak akses locators // Username textbox locator private By usernameLocator = By.id("username"); // Password textbox locator private By passwordLocator = By.id("password"); // Login button locator private By loginBtnLocator = By.id("login-btn"); // "Forgot Password?" link locator private By forgotPwdLocator = By.linkText("Forgot Password?"); // Error message locator (shows when login fails) private By errorMsgLocator = By.id("error-msg"); // Welcome message locator (shows when login succeeds) private By welcomeMsgLocator = By.id("welcome-msg"); // ============ CONSTRUCTOR ============ /** * Constructor - initialize LoginPage dengan WebDriver * Test class akan: new LoginPage(driver) * Constructor akan initialize this.driver and this.wait */ public LoginPage(WebDriver driver) { // Store driver reference this.driver = driver; // Initialize wait dengan 10 seconds timeout this.wait = new WebDriverWait( driver, Duration.ofSeconds(10) ); } // ============ PAGE ACTIONS (METHODS) ============ /** * fillUsername - Fill username textbox * @param username - username to enter * * Logic: * 1. Wait sampai username field visible * 2. Type username */ public void fillUsername(String username) { // Wait for username field sampai visible // visibilityOfElementLocated = element ada + visible + enabled WebElement usernameField = wait.until( ExpectedConditions.visibilityOfElementLocated(usernameLocator) ); // Clear field dulu (jika ada data sebelumnya) usernameField.clear(); // Type username usernameField.sendKeys(username); } /** * fillPassword - Fill password textbox * @param password - password to enter */ public void fillPassword(String password) { // Find password field (tidak perlu wait, assume sebelumnya sudah visible) WebElement passwordField = driver.findElement(passwordLocator); // Clear field passwordField.clear(); // Type password passwordField.sendKeys(password); } /** * clickLoginButton - Click login button * * Logic: * 1. Wait until button clickable * 2. Click button */ public void clickLoginButton() { // Wait until button clickable // elementToBeClickable = visible + enabled + clickable WebElement loginBtn = wait.until( ExpectedConditions.elementToBeClickable(loginBtnLocator) ); // Click button loginBtn.click(); } /** * login - Complete login flow * @param username - username * @param password - password * * Logic: * 1. Fill username * 2. Fill password * 3. Click login * * Why create this method? * Convenience method untuk test class * Tidak perlu call 3 methods, hanya 1 call */ public void login(String username, String password) { fillUsername(username); fillPassword(password); clickLoginButton(); } /** * getErrorMessage - Get error message text * @return error message string * * Used when: login fails, want to verify error message */ public String getErrorMessage() { // Wait until error message visible WebElement errorMsg = wait.until( ExpectedConditions.visibilityOfElementLocated(errorMsgLocator) ); // Return text return errorMsg.getText(); } /** * getWelcomeMessage - Get welcome message text * @return welcome message string * * Used when: login succeeds, want to verify welcome message */ public String getWelcomeMessage() { // Wait until welcome message visible (indicator ng successful login) WebElement welcomeMsg = wait.until( ExpectedConditions.visibilityOfElementLocated(welcomeMsgLocator) ); return welcomeMsg.getText(); } /** * isErrorMessageDisplayed - Check if error message shows * @return true jika error message visible, false otherwise */ public boolean isErrorMessageDisplayed() { try { WebElement errorMsg = wait.until( ExpectedConditions.visibilityOfElementLocated(errorMsgLocator) ); return errorMsg.isDisplayed(); } catch (TimeoutException e) { // Element tidak visible within 10 seconds return false; } } /** * clickForgotPassword - Click "Forgot Password?" link */ public void clickForgotPassword() { WebElement forgotLink = driver.findElement(forgotPwdLocator); forgotLink.click(); } }
Key Points:
1. Private By locators: Hanya LoginPage yang tahu locators. Test class tidak tahu.
2. Constructor: Initialize driver & wait. Test akan: new LoginPage(driver)
3. Methods untuk setiap action: fillUsername(), fillPassword(), clickLoginButton(), login() (combination)
4. Methods untuk verify: getErrorMessage(), getWelcomeMessage(), isErrorMessageDisplayed()
5. Waits & error handling: Semua handled di page class, tidak di test class
6. Comments: Setiap method punya javadoc explaining what it does
🔊 "Default, testng run tests sequentially - test 1 finish, test 2 start, test 3 start. Nếu 100 tests, masing-masing 5 detik, total 500 detik. Tapi jika tests independent (tidak share state), bisa run parallel - test 1, 2, 3 run simultaneously. Total time = 5 detik (fastest test time). Testng support parallel execution. Di testng.xml: <suite parallel='methods' thread-count='4'>. Nó akan run tests parallel dengan 4 threads. Setiap thread run independent test method. Kalo parallel='classes', run classes parallel. Kalo parallel='tests', run test tags parallel. Thread-count specify berapa threads. Kalau 4 threads dan 100 tests, total time = 100/4 * 5 = 125 detik. Versus 500 detik sequential, hemat 75% time! Tapi penting: tests HARUS independent. Jika test A modify state yg test B depend on, parallel execution error. Ví dụ, test A create user 'john@example.com', test B expect user not exist - jika run parallel, bisa conflict. Solution: masing-masing test setup sendiri data, cleanup sendiri data, tidak share state. Atau gunakan fixture scope properly - @BeforeMethod create fresh data, @AfterMethod cleanup."

Sebelum POM (❌ Buruk):

public class BadLoginTest { @Test public void testLogin() { // Locators scattered di test class WebElement username = driver.findElement(By.id("username")); username.sendKeys("john@example.com"); WebElement password = driver.findElement(By.id("password")); password.sendKeys("password123"); driver.findElement(By.id("login-btn")).click(); WebElement welcome = driver.findElement(By.id("welcome-msg")); Assert.assertTrue(welcome.getText().contains("Welcome")); } } // Problem: hardcoded locators, test logic mixed with UI details // UI change (id="username" → id="user")? Sesudah POM (✅ Baik):

public class LoginTestWithPOM { // Declare LoginPage page object LoginPage loginPage; // Declare WebDriver WebDriver driver; @BeforeClass public void beforeClass() { // Initialize browser driver = new ChromeDriver(); driver.get("https://example.com/login"); // Initialize LoginPage with driver // LoginPage constructor will set this.driver and this.wait loginPage = new LoginPage(driver); } // Test 1: Valid login @Test public void testValidLogin() { // Test logic is CLEAN and SIMPLE // Just call page methods, no worries about locators // Call loginPage.login() method loginPage.login("john@example.com", "password123"); // Get welcome message from page String welcomeMsg = loginPage.getWelcomeMessage(); // Assert Assert.assertTrue( welcomeMsg.contains("Welcome"), "Welcome message should appear" ); } // Test 2: Invalid login @Test public void testInvalidLogin() { // Call login with wrong password loginPage.login("john@example.com", "wrongpassword"); // Get error message String errorMsg = loginPage.getErrorMessage(); // Assert Assert.assertTrue( errorMsg.contains("Invalid credentials"), "Error message should show" ); } // Test 3: Empty username @Test public void testEmptyUsername() { // Don't fill username, just password loginPage.fillPassword("password123"); loginPage.clickLoginButton(); // Check error message Assert.assertTrue( loginPage.isErrorMessageDisplayed(), "Error should show for empty username" ); } @AfterClass public void afterClass() { driver.quit(); } } // Advantages: // 1. Test code clean, readable, intent jelas // 2. No locators di test class (all in LoginPage) // 3. UI change? Edit LoginPage, all tests work automatically // 4. Reusable: add 100 more tests, reuse same LoginPage methods // 5. Maintainable: 1 place to update for UI changes

Comparison:

Aspect Without POM With POM
Test readability Messy (locators + logic) ✅ Clean (just methods)
Maintenance Hard (change in 50+ tests) ✅ Easy (change in 1 page class)
Reusability Low (copy-paste) ✅ High (share methods)
Lines of code per test 20+ lines ✅ 3-5 lines
Test data + test logic Mixed ✅ Separated
🔊 "Kita sudah lihat Selenium code itu bisa messy jika mix page interaction dengan test logic. Test code punya locators hardcoded, methods scattered. Nanti jika UI change, perlu update banyak test code. PAGE OBJECT MODEL adalah design pattern untuk organize Selenium code. Ide: buat separate class untuk setiap page dalam aplikasi. Class ini capsulate semua page-specific stuff: locators, methods to interact dengan page. Test code hanya call methods dari page class, tidak tau tentang locators atau DOM structure. Benefits: DRY - Don't Repeat Yourself. Locators define once, reuse many tests. Maintainability - UI change, update page class, tests tidak perlu change. Readability - test code read like natural language: loginPage.login('john', 'pass'). Test code focus pada test logic, bukan implementation details. Ví dụ, LoginPage class. Private By locators - usernameLocator, passwordLocator, loginButtonLocator, errorMessageLocator. Public methods - login(username, password), getErrorMessage(), isErrorMessageDisplayed(). Constructor accept WebDriver untuk initialize locators. Test code: LoginPage page = new LoginPage(driver). page.login('john@example.com', 'password123'). Assert.assertTrue(driver.getCurrentUrl().contains('/dashboard'))."

📊 Data-Driven Testing

Masalah: Berulang-Ulang Untuk Multiple Data

Ingin test login dengan 5 usernames berbeda:

// ❌ Buruk: Tulis 5 test methods hampir identik @Test public void testLogin1() { loginPage.login("user1@test.com", "pass1"); } @Test public void testLogin2() { loginPage.login("user2@test.com", "pass2"); } @Test public void testLogin3() { loginPage.login("user3@test.com", "pass3"); } // ... 4 more methods ... // Total: 5 methods yang code-nya 99% sama!

Solusi: Data-Driven Testing dengan @DataProvider

TestNG @DataProvider memungkinkan 1 method run dengan multiple data sets

public class DataDrivenLoginTest { LoginPage loginPage; WebDriver driver; @BeforeMethod public void setUp() { driver = new ChromeDriver(); driver.get("https://example.com/login"); loginPage = new LoginPage(driver); } /** * @DataProvider - Provide test data * Return Object[][] dengan multiple test cases * * Setiap row adalah 1 set data untuk 1 test execution * Format: {username, password, expectedMessage} */ @DataProvider(name = "loginTestData") public Object[][] getLoginTestData() { return new Object[][] { // Test case 1: Valid login {"john@example.com", "password123", "Welcome"}, // Test case 2: Different valid user {"jane@example.com", "securepass", "Welcome"}, // Test case 3: Another user {"bob@example.com", "mypassword", "Welcome"}, // Test case 4: Corporate account {"admin@company.com", "admin123", "Welcome"}, }; } /** * testLoginWithMultipleUsers - Same test method run untuk setiap data set * @param username - dari @DataProvider row * @param password - dari @DataProvider row * @param expectedMsg - dari @DataProvider row * * How it works: * 1. TestNG read getLoginTestData() -> returns 4 rows * 2. testLoginWithMultipleUsers() run 4 times * 3. Each run gunakan data dari 1 row * 4. Output: 4 test executions dengan different data */ @Test(dataProvider = "loginTestData") public void testLoginWithMultipleUsers( String username, String password, String expectedMsg ) { // Login dengan data dari @DataProvider loginPage.login(username, password); // Get welcome message String welcomeMsg = loginPage.getWelcomeMessage(); // Assert dengan expected message dari data Assert.assertTrue( welcomeMsg.contains(expectedMsg), "Welcome message should contain: " + expectedMsg ); // Log successful test execution System.out.println("✅ Login successful for: " + username); } @AfterMethod public void tearDown() { driver.quit(); } } // Output when run: // Test 1: testLoginWithMultipleUsers[john@example.com, password123, Welcome] - PASSED // Test 2: testLoginWithMultipleUsers[jane@example.com, securepass, Welcome] - PASSED // Test 3: testLoginWithMultipleUsers[bob@example.com, mypassword, Welcome] - PASSED // Test 4: testLoginWithMultipleUsers[admin@company.com, admin123, Welcome] - PASSED // Total: 4 tests executed from 1 method!

Keuntungan Data-Driven Testing:

  • ✅ 1 method, multiple executions: Reduce code duplication
  • ✅ Easy to add more data: Just add 1 row di DataProvider
  • ✅ Test report shows all executions: 4 data sets = 4 test results
  • ✅ Easier to maintain: 1 test logic, separate data
🔊 "Hãy viết LoginPage class theo POM. Package: pages, class name: LoginPage. Constructor: public LoginPage(WebDriver driver). Store driver: this.driver = driver. Initialize WebDriverWait: this.wait = new WebDriverWait(driver, Duration.ofSeconds(10)). Locators: private By usernameLocator = By.id('username'), private By passwordLocator = By.name('password'), private By loginButtonLocator = By.cssSelector('button.login'), private By welcomeMessageLocator = By.className('welcome'), private By errorMessageLocator = By.className('error'). Methods: public void fillUsername(String username) { wait.until(ExpectedConditions.visibilityOfElementLocated(usernameLocator)).sendKeys(username). } - wait untuk element visible, then fill username. public void fillPassword(String password) { driver.findElement(passwordLocator).sendKeys(password). } public void clickLoginButton() { driver.findElement(loginButtonLocator).click(). } public String login(String username, String password) { fillUsername(username). fillPassword(password). clickLoginButton(). } - compound method. public String getWelcomeMessage() { return wait.until(ExpectedConditions.visibilityOfElementLocated(welcomeMessageLocator)).getText(). } public String getErrorMessage() { return driver.findElement(errorMessageLocator).getText(). } public boolean isErrorMessageDisplayed() { try { return driver.findElement(errorMessageLocator).isDisplayed(). } catch (NoSuchElementException e) { return false. } }. Best practice: return types explicit, methods single responsibility, waits explicit, error handling proper."

⚙️ TestNG XML & Parallel Execution

TestNG XML Configuration

File testng.xml untuk configure test execution

Contoh testng.xml:

<?xml version="1.0" encoding="UTF-8"?> <suite name="LoginTestSuite" parallel="methods" thread-count="4"> <!-- Suite: group of tests --> <!-- parallel="methods": run @Test methods in parallel --> <!-- thread-count="4": use 4 threads --> <test name="LoginTests"> <classes> <!-- Run all tests in LoginTest class --> <class name="tests.LoginTest"> <!-- Optional: run specific methods only --> <methods> <include name="testValidLogin"/> <include name="testInvalidLogin"/> </methods> </class> </classes> </test> <test name="HomeTests"> <classes> <class name="tests.HomeTest"/> </classes> </test> </suite>

Parallel Execution Options:

// Option 1: Run methods in parallel <suite parallel="methods" thread-count="4"> // Jalankan 4 @Test methods sekaligus di 4 threads // Useful untuk fast execution // Tapi perlu caution: avoid conflicts (e.g., shared resources) // Option 2: Run classes in parallel <suite parallel="classes" thread-count="3"> // Run LoginTest, HomeTest, DashboardTest sekaligus di 3 threads // Option 3: Run tests sequentially (default) <suite parallel="false"> // Run tests one by one (slower tapi safe)

Run testng.xml:

// Option 1: From IDE (right-click testng.xml → Run) // Option 2: From command line $ mvn clean test // Option 3: Run specific XML $ mvn test -Dsuites=src/test/resources/testng.xml // Output with parallel execution: // Thread-1: testValidLogin() running // Thread-2: testInvalidLogin() running // Thread-3: testEmptyUsername() running // Thread-4: testLoginEmptyPassword() running // (All 4 tests run simultaneously)

Performance Impact:

  • Sequential (1 thread): 4 tests × 5 seconds = 20 seconds
  • Parallel (4 threads): 4 tests ÷ 4 threads = 5 seconds ⚡
  • Speedup: 4x faster! (20s → 5s)
⚠️ Caution: Parallel execution can cause issues jika tests share resources (e.g., same database). Isolate tests untuk parallel execution.
🔊 "Ngoài static test methods, TestNG support data-driven testing - run same test dengan different data. @DataProvider annotation provide data ke test method. Ví dụ, test login dengan multiple users: john/pass1, jane/pass2, bob/pass3. Thay vì viết 3 test methods, viết 1 test method, @DataProvider provide 3 sets data. @DataProvider(name='loginData') public Object[][] getLoginData() { return new Object[][] { {'john@example.com', 'password123'}, {'jane@example.com', 'securepass'}, {'bob@example.com', 'anotherpass'} }; }. @DataProvider return 2D array - masing-masing row adalah 1 set data. @Test(dataProvider='loginData') public void testLogin(String username, String password) { loginPage.login(username, password). String welcome = driver.findElement(...).getText(). Assert.assertTrue(welcome.contains('Welcome')). }. TestNG sẽ run testLogin 3 times, dengan data berbeda setiap kali. Output: testLogin[0] - dengan data row 0, testLogin[1] - dengan data row 1, testLogin[2] - dengan data row 2. Jika salah satu fail, report menunjukan testLogin[1] fail, bukan just 'testLogin fail'. Benefits: single test logic, multiple data sets, easy add more test cases (just add row to data provider)."

  • ✅ TestNG Framework: Organize test cases, fixtures, annotations
