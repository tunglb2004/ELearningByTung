Tại Sao OOP Quan Trọng?

OOP là nền tảng của lập trình modern. Hiểu rõ OOP sẽ giúp bạn:

  • ✅ Viết code clean và maintainable
  • ✅ Tái sử dụng code (reusable)
  • ✅ Giải quyết bài toán phức tạp một cách có tổ chức
  • ✅ Dễ collaborate với team
🔊 "Hôm nay chúng ta sẽ tìm hiểu về OOP - Object-Oriented Programming, một trong những paradigm quan trọng nhất trong lập trình. OOP không chỉ là một cơ chế lập trình, mà nó là một cách suy nghĩ. Khi bạn nhìn vào một bài toán, bạn không chỉ nhìn thấy dòng code, mà bạn nhìn thấy những đối tượng (objects) và mối quan hệ giữa chúng. Dưới đây là ví dụ thực tế. Khi bạn đi mua sắm, bạn không gọi 'cái quần', bạn gọi 'cái quần xanh'. Đó là abstraction. Bạn không quan tâm làm sao nó được may, bạn chỉ quan tâm nó có vừa không. Đó là encapsulation - ẩn chi tiết phức tạp. Bạn có một loại quần (class cha), từ đó có thể có quần jean, quần khaki, quần thun (inheritance). Khi bạn mặc quần, cách mặc là như nhau, nhưng kết quả lại khác (polymorphism). Chúng ta sẽ khám phá 4 trụ cột này một cách chi tiết, kèm theo code examples thực tế."

🔐 Encapsulation (Đóng Gói)

Encapsulation Là Gì?

Encapsulation = "Đóng gói", ẩn chi tiết nội bộ của object. Người dùng chỉ nhìn thấy interface (public methods), không nhìn thấy implementation (private variables).

Kiểu so sánh: Khi bạn bấm remote TV, bạn không cần biết bên trong nó hoạt động như nào. Bạn chỉ biết: nhấn nút lên → âm thanh tăng. Đó là encapsulation.

Lợi Ích của Encapsulation

  • ✅ Bảo vệ dữ liệu: Không cho phép thay đổi dữ liệu trực tiếp
  • ✅ Dễ bảo trì: Thay đổi implementation mà không ảnh hưởng code khác
  • ✅ Enforce constraints: Đảm bảo dữ liệu luôn hợp lệ (ví dụ: balance không âm)

Code Example:

public class BankAccount { // Private - chỉ truy cập từ trong class private double balance = 0; private String accountNumber; // Constructor public BankAccount(String accountNumber, double initialBalance) { this.accountNumber = accountNumber; this.balance = initialBalance; } // Public method: deposit (gửi tiền) public boolean deposit(double amount) { if (amount <= 0) { System.out.println("❌ Error: Amount must be positive"); return false; } balance += amount; System.out.println("✅ Deposited: " + amount); return true; } // Public method: withdraw (rút tiền) public boolean withdraw(double amount) { if (amount <= 0 || amount > balance) { System.out.println("❌ Error: Invalid amount"); return false; } balance -= amount; return true; } // Public getter: xem số dư public double getBalance() { return balance; } }
✅ Chú ý: balance là private → User không thể làm account.balance = -1000 (vi phạm logic). Phải dùng methods deposit() và withdraw() để đảm bảo constraints.
🔊 "Encapsulation là một trong những concepts quan trọng nhất. Hãy tưởng tượng bạn viết một class để quản lý tài khoản ngân hàng. Nếu bạn public balance variable, user có thể làm account.balance = -999999, điều đó vi phạm logic business. Vì vậy bạn đặt balance là private, và cung cấp public methods như deposit() và withdraw(). Bên trong những methods này, bạn có thể: 1. Validate dữ liệu (kiểm tra amount > 0) 2. Log transactions (ghi lại giao dịch) 3. Update multiple related fields (cập nhật balance và lastTransaction date) 4. Trigger notifications (thông báo cho user) Điều này gọi là 'Separation of Concerns'. Business logic (validate, log) được tách riêng khỏi data access."

🧬 Inheritance (Kế Thừa)

Inheritance Là Gì?

Inheritance = Class con kế thừa từ class cha, được tất cả properties và methods của class cha.

Kiểu so sánh: Một con Dog kế thừa từ Animal. Dog có tất cả đặc tính của Animal (có bốn chân, ăn cơm), nhưng Dog có thêm đặc tính riêng (sủa, cắn).

Tại Sao Dùng Inheritance?

  • ✅ Code Reuse: Không phải viết lại code
  • ✅ Establish Hierarchy: Tạo mối quan hệ giữa classes
  • ✅ Polymorphism: Cho phép override methods (chúng ta sẽ học sau)

Code Example:

// Class cha (parent/superclass) public class Animal { private String name; private int age; public Animal(String name, int age) { this.name = name; this.age = age; } public void eat() { System.out.println(name + " is eating"); } public void sleep() { System.out.println(name + " is sleeping"); } public String getName() { return name; } } // Class con (child/subclass) public class Dog extends Animal { private String breed; public Dog(String name, int age, String breed) { super(name, age); // Gọi parent constructor this.breed = breed; } // Override method eat() @Override public void eat() { System.out.println(getName() + " is eating meat"); } // Method riêng của Dog public void bark() { System.out.println(getName() + " says: Woof!"); } }
💡 Tips: extends là keyword để kế thừa. super() để gọi parent constructor. @Override annotation để báo override method.
🔊 "Inheritance giải quyết vấn đề code duplication. Nếu bạn không có inheritance, bạn phải viết eat(), sleep() ở cả Dog, Cat, Bird, ... Với inheritance, bạn viết một lần ở Animal, tất cả animal subclasses đều có. Nếu Animal có 100 methods, Dog sẽ kế thừa tất cả 100. Nhưng chú ý, inheritance không phải lúc nào cũng phù hợp. Kiểm tra quan hệ 'is-a'. Nếu Dog 'is-a' Animal, dùng inheritance. Nếu Dog 'has-a' Collar, dùng composition (chúng ta sẽ học sau)."

🎭 Polymorphism (Đa Hình)

Polymorphism Là Gì?

Polymorphism = "Nhiều hình dạng". Cùng method name nhưng có implementations khác nhau tùy class.

Kiểu so sánh: Nút 'On' ở remote TV, remote điều hòa, remote máy giặt... tên giống nhau nhưng chức năng khác. Đó là polymorphism.

2 Loại Polymorphism

  • Compile-time: Method Overloading (cùng method name, parameters khác)
  • Runtime: Method Overriding (cùng method signature, implementation khác)

Runtime Polymorphism (Overriding):

public class Shape { public void draw() { System.out.println("Drawing a shape"); } } public class Circle extends Shape { @Override public void draw() { System.out.println("🔵 Drawing a circle"); } } public class Rectangle extends Shape { @Override public void draw() { System.out.println("▭ Drawing a rectangle"); } } // Sử dụng Polymorphism public static void main(String[] args) { Shape shape1 = new Circle(); Shape shape2 = new Rectangle(); shape1.draw(); // Output: 🔵 Drawing a circle shape2.draw(); // Output: ▭ Drawing a rectangle // Cùng method name, khác output! }
✅ Magic: Dù shape1 và shape2 đều kiểu Shape, nhưng draw() sẽ gọi method của runtime type (Circle hoặc Rectangle), không phải compile-time type.
🔊 "Polymorphism là feature mạnh nhất của OOP. Nó cho phép bạn viết code generic, xử lý nhiều types mà không cần biết chính xác type nào. Ví dụ, nếu bạn có một array chứa nhiều Shapes, bạn có thể loop qua tất cả và gọi draw() mà không cần biết draw() sẽ làm gì: Shape[] shapes = {new Circle(), new Rectangle(), new Triangle()}; for (Shape shape : shapes) { shape.draw(); // Tự động gọi đúng method cho từng type! } Điều này gọi là 'loose coupling'. Code của bạn không phụ thuộc vào implementation details của Shape subclasses."

☁️ Abstraction (Trừu Tượng)

Abstraction Là Gì?

Abstraction = Ẩn complexity, chỉ show những cần thiết. Dùng abstract class hoặc interface.

Kiểu so sánh: Bạn dùng USB cable, bạn không cần biết bên trong nó hoạt động như nào (voltage, protocol...), bạn chỉ cắm vào. Đó là abstraction.

Abstract Class vs Interface

  • Abstract Class: Có thể có concrete methods (có body) + abstract methods (không body)
  • Interface: Chỉ có abstract methods (Java 8+ có default methods)

Code Example: Abstract Class

public abstract class Database { protected String connectionString; public Database(String connectionString) { this.connectionString = connectionString; } // Abstract methods - subclass PHẢI implement public abstract void connect(); public abstract void disconnect(); // Concrete method - subclass có thể dùng hoặc override public void startTransaction() { System.out.println("Starting transaction..."); } } public class MySQLDatabase extends Database { @Override public void connect() { System.out.println("🔗 Connecting to MySQL"); } @Override public void disconnect() { System.out.println("🔌 Disconnecting from MySQL"); } } public class PostgreSQLDatabase extends Database { @Override public void connect() { System.out.println("🔗 Connecting to PostgreSQL"); } @Override public void disconnect() { System.out.println("🔌 Disconnecting from PostgreSQL"); } }
💡 Lợi Ích: Abstraction định nghĩa contract (interface), implementation có thể thay đổi. Code test có thể work với Database reference, dù underlying là MySQL hay PostgreSQL.
🔊 "Abstraction là foundation của framework design. Khi bạn design một framework, bạn không muốn users biết details. Bạn define abstract class hoặc interface, users implement cái đó. Ví dụ, Spring Framework sử dụng Abstraction rất nhiều. Nó define Repository interface, bạn implement nó để connect DB khác nhau. Framework không quan tâm bạn dùng MySQL hay MongoDB. Lợi ích: 1. Flexibility - easily swap implementations 2. Testability - mock abstract interface 3. Maintainability - change implementation without affecting clients 4. Extensibility - add new implementations"

📚 Recap: 4 OOP Principles

1. Encapsulation (Đóng Gói)

  • ✅ Ẩn private variables, expose public methods
  • ✅ Protect data integrity
  • ✅ "Data hiding"

2. Inheritance (Kế Thừa)

  • ✅ Child class kế thừa từ parent class
  • ✅ Reuse code, establish hierarchy
  • ✅ "is-a" relationship

3. Polymorphism (Đa Hình)

  • ✅ Same method name, different implementations
  • ✅ Runtime type determines which method to call
  • ✅ "one interface, many forms"

4. Abstraction (Trừu Tượng)

  • ✅ Hide complexity, show interface
  • ✅ Abstract classes + interfaces
  • ✅ Define contract for implementations
✅ Tổng Kết: 4 principles này phối hợp với nhau tạo nên powerful, flexible, maintainable code architecture.
🔊 "Chúng ta vừa hoàn thành PHẦN 1: OOP Principles. Những concepts này không chỉ dùng cho Java, mà dùng cho hầu hết các ngôn ngữ OOP: C++, C#, Python, JavaScript... Khi bạn design một class, hãy suy nghĩ: 1. Encapsulation: Dữ liệu nào nên private? Dữ liệu nào nên public? 2. Inheritance: Có class cha chung không? Có thể extract common code? 3. Polymorphism: Có method nào nên override ở subclasses? 4. Abstraction: Có thể define abstract interface để multiple implementations? Hãy nhớ: 'Code is read more often than it is written'. Viết code theo OOP principles sẽ giúp người khác (hoặc chính bạn sau này) dễ hiểu và maintain code của bạn."
